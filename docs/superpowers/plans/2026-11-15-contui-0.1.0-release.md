# contUI 0.1.0 bottle release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tagging `v0.1.0` publishes a source tarball plus an `arm64_tahoe` Homebrew bottle, so `brew install adgan/tap/contui` on arm64 macOS 26 pours a prebuilt app with no Rust compile.

**Architecture:** Three small shell scripts do the work (`release-tarball.sh` → `generate-formula.sh` → `build-bottle.sh`). A two-job GitHub Actions workflow, started **only by manual dispatch**, keeps the macOS minutes minimal: `ubuntu-24.04-arm` makes the tarball, creates the release and writes the stable formula; only then does `macos-26` run `brew install --build-bottle`, `brew bottle`, and the upload. The tap formula gains a stable `url`, a `sha256`, a `bottle do` block, and hard platform gates.

**Tech Stack:** Bash, Homebrew (`brew bottle`, `--build-bottle`, `--merge --write`), GitHub Actions (`ubuntu-24.04-arm` + `macos-26`), `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-11-15-contui-0.1.0-release-design.md`

## Global Constraints

- Bottle label is exactly `arm64_tahoe`; the only built platform is arm64 macOS 26.
- Version under release is `0.1.0`; tag is exactly `v0.1.0`; `CFBundleVersion` stays `1`.
- Source tarball is our own release asset, never `archive/refs/tags/...`.
- Tap repo is `/opt/homebrew/Library/Taps/adgan/homebrew-tap` (public, `homebrew-tap`).
- Bottle hosted as a GitHub release asset; `root_url` is `https://github.com/adgan/contui/releases/download/v<version>`. No ghcr.io, no `TAP_TOKEN`, no cross-repo push.
- The tap formula keeps `head` and `depends_on "rust" => :build`; `rust` must never be installed when pouring a bottle.
- Ad-hoc signing stays (`codesign --force --deep --sign -`); no notarization.
- Scripts are `set -euo pipefail`, take the version as `$1`, and write only under the given output directory plus the tap checkout.
- The release workflow is **`workflow_dispatch` only** — no `push: tags` trigger, so a stray tag never starts a macOS job. It takes one input, `version` (e.g. `0.1.0`), and checks out `v<version>`.
- **macOS time is the scarce resource.** The `macos-26` job may contain only `brew install --build-bottle`, `brew bottle` ×2, the bottle upload, and the summary — no tarball building, no formula generation, no cloning, no release creation, and a `scripts`-only checkout (`sparse-checkout: scripts`).
- `ubuntu-24.04-arm` job: `timeout-minutes: 10`. `macos-26` job: `timeout-minutes: 25`. Both under `concurrency: release`.

## Review Focus

- **A machine that cannot pour** (Intel, Sequoia): `brew install` must stop with a clear "requires macOS Tahoe / arm64" error, not compile for 90 seconds.
- **Checksum drift**: the tarball we host and the sha in the tap formula must be the same bytes forever; a regenerated tag must never silently reuse an old sha.
- **Empty bundle in the tarball**: `assets/fonts` is what `install` copies with `cp_r` behind an `exist?` guard, so a missing `assets/` in the tarball produces a fontless app that still installs.
- **Bottle that is really a keg of the wrong shape**: the poured keg must contain `contUI.app/Contents/MacOS/contUI` plus the `bin/contui` symlink, because that is what the app and the CLI both expect.
- **Tap drift after the release**: the formula printed by CI and the formula committed to the tap must match byte for byte, or `brew install` reports a checksum mismatch.
- **A macOS job that silently does more than bottle**: if the split regresses (macOS starts generating formulas or building tarballs again), macOS minutes creep back up with no visible symptom.

- [ ] **Step 3: Implement `scripts/generate-formula.sh`**

Reads the base file, prints it with the `bottle do … end` block removed, then inserts after the `version "…"` line:

```sh
#!/usr/bin/env bash
# Rewrites a tap formula for a tagged release: stable url + sha, no bottle block.
# usage: generate-formula.sh <version> <tarball-url> <sha256> <base-formula>
set -euo pipefail
version="$1" url="$2" sha="$3" base="$4"

grep -qx "  version \"$version\"" "$base" || {
  echo "generate-formula.sh: $base has no 'version \"$version\"' line" >&2
  exit 1
}

awk -v url="$url" -v sha="$sha" -v version="$version" '
  $0 ~ /^[[:space:]]*bottle do[[:space:]]*$/ { inbottle = 1; next }
  inbottle && $0 ~ /^[[:space:]]*end[[:space:]]*$/ { inbottle = 0; next }
  inbottle { next }
  { print }
  $0 == "  version \"" version "\"" {
    print "  url \"" url "\""
    print "  sha256 \"" sha "\""
  }
' "$base"
```

Emit nothing else: no trailing blank line, no debug output, because the caller feeds the result straight into the tap formula file.

**Interfaces:**
- Consumes: `scripts/generate-formula.sh` (Task 2), the tap formula (Task 1).
- Produces:
  - `scripts/release-tarball.sh <version> <dist-dir>` → `dist/contui-<version>.tar.gz`; prints the sha256 on stdout, one line.
  - `scripts/prepare-release.sh <version> <dist-dir> [url-base] [tap-url]` → tarball plus `dist/contui.rb` (stable `url`/`sha256`, no bottle block). Needs no macOS and no Homebrew.
  - `scripts/build-bottle.sh <version> <dist-dir> [url-base]` → reads `dist/contui.rb`, installs it in the tap, bottles into `dist/contui--<version>.arm64_tahoe.bottle.tar.gz` (+ `.json`), merges the bottle block back, and overwrites `dist/contui.rb` with the final formula. macOS only.
  - `dist/contui.rb` is the single handoff: `prepare-release.sh` writes it, `build-bottle.sh` finalises it.

- [ ] **Step 1: Write `scripts/release-tarball.sh`**

```sh
#!/usr/bin/env bash
# usage: release-tarball.sh <version> <dist-dir> ; prints sha256
set -euo pipefail
version="$1" dist="$2"
mkdir -p "$dist"
tarball="$dist/contui-$version.tar.gz"
git archive --format=tar.gz --prefix="contui-$version/" -o "$tarball" "v$version"
shasum -a 256 "$tarball" | awk '{print $1}'
```

Fails loudly if the tag is missing (`git archive` exits non-zero) — intended: the tarball must come from the tag, not the working tree.

- [ ] **Step 2: Write `scripts/prepare-release.sh`**

```sh
#!/usr/bin/env bash
# Everything that does not need macOS: source tarball + stable formula.
# usage: prepare-release.sh <version> <dist-dir> [url-base] [tap-url]
set -euo pipefail
version="$1" dist="$2"
url_base="${3:-https://github.com/adgan/contui/releases/download/v$version}"
tap_url="${4:-https://github.com/adgan/homebrew-tap.git}"

mkdir -p "$dist"
sha="$(scripts/release-tarball.sh "$version" "$dist")"
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT
git clone --depth 1 --quiet "$tap_url" "$tmp/tap"
scripts/generate-formula.sh "$version" "$url_base/contui-$version.tar.gz" "$sha" \
  "$tmp/tap/Formula/contui.rb" > "$dist/contui.rb"
echo "$sha"
```

- [ ] **Step 3: Write `scripts/build-bottle.sh`**

```sh
#!/usr/bin/env bash
# The only macOS step: install the prepared formula with --build-bottle, bottle it,
# write the bottle block back into the formula. Needs dist/contui.rb from prepare-release.sh.
# usage: build-bottle.sh <version> <dist-dir> [url-base]
set -euo pipefail
version="$1" dist="$2"
url_base="${3:-https://github.com/adgan/contui/releases/download/v$version}"
tap="$(brew --repository adgan/tap)"
formula="$dist/contui.rb"

[ -f "$formula" ] || { echo "build-bottle.sh: no $formula" >&2; exit 1; }
brew tap adgan/tap >/dev/null 2>&1 || true
cp "$formula" "$tap/Formula/contui.rb"

HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 \
  brew install --build-bottle adgan/tap/contui
(cd "$dist" && HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 \
  brew bottle --json --no-rebuild --root-url "$url_base" adgan/tap/contui)
json="$(ls "$dist"/contui--"$version".*.bottle.json)"
brew bottle --merge --write --no-commit "$json"
cp "$tap/Formula/contui.rb" "$formula"

ls -1 "$dist"/contui--*.bottle.tar.gz "$formula"
```

Two `brew bottle` invocations on purpose: the first produces the tarball and JSON, the second writes the DSL into the formula. Never hand-write the `sha256` or the `cellar:` value.

- [ ] **Step 7: Write the two-job release workflow**

`.github/workflows/release.yml` — dispatched by hand, never by a tag push:

```yaml
name: release

on:
  workflow_dispatch:
    inputs:
      version:
        description: "Version to release, without the v (e.g. 0.1.0)"
        required: true
        type: string

permissions:
  contents: write

concurrency: release

jobs:
  prepare:
    runs-on: ubuntu-24.04-arm
    timeout-minutes: 10
    env:
      GH_TOKEN: ${{ github.token }}
      VERSION: ${{ inputs.version }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: refs/tags/v${{ inputs.version }}
      - name: Check tag matches Cargo.toml
        run: grep -qx "version = \"$VERSION\"" Cargo.toml
      - name: Create the release
        run: |
          gh release view "v$VERSION" >/dev/null 2>&1 && exit 0
          notes=".github/release-notes/$VERSION.md"
          if [ -f "$notes" ]; then
            gh release create "v$VERSION" --title "contUI $VERSION" --notes-file "$notes"
          else
            gh release create "v$VERSION" --title "contUI $VERSION" --generate-notes
          fi
      - name: Build source tarball and stable formula
        run: scripts/prepare-release.sh "$VERSION" dist
      - name: Publish source tarball
        run: gh release upload "v$VERSION" dist/contui-*.tar.gz --clobber
      - uses: actions/upload-artifact@v4
        with:
          name: formula-base
          path: dist/contui.rb

  bottle:
    needs: prepare
    runs-on: macos-26
    timeout-minutes: 25
    env:
      GH_TOKEN: ${{ github.token }}
      VERSION: ${{ inputs.version }}
      HOMEBREW_NO_AUTO_UPDATE: 1
      HOMEBREW_NO_INSTALL_CLEANUP: 1
      HOMEBREW_NO_ANALYTICS: 1
      HOMEBREW_NO_ENV_HINTS: 1
    steps:
      - uses: actions/checkout@v4
        with:
          ref: refs/tags/v${{ inputs.version }}
          sparse-checkout: scripts
      - uses: actions/download-artifact@v4
        with:
          name: formula-base
          path: dist
      - name: Build bottle
        run: scripts/build-bottle.sh "$VERSION" dist
      - name: Publish bottle
        run: gh release upload "v$VERSION" dist/*.bottle.tar.gz --clobber
      - name: Publish formula for the tap
        run: cat dist/contui.rb >> "$GITHUB_STEP_SUMMARY"
      - uses: actions/upload-artifact@v4
        with:
          name: formula
          path: dist/contui.rb
```

`needs: prepare` is what guarantees the tarball is on the release before `brew install --build-bottle` fetches it. The workflow never pushes to the tap. Because it is dispatch-only, the tag must exist before dispatching — `gh workflow run` reads the workflow from the default branch, then the checkout pins the tag.
